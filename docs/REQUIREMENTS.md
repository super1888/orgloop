# OrgLoop 需求基线

## 1. 文档地位与目标

本仓库当前交付是可审阅的设计基线，应用尚未实现。本文件中的“应”表示目标行为；场景、API 或检查存在，不代表相应行为已经实现或验证。静态文档检查、契约检查、应用运行、实际组织效果及用户验收分别记录，证据入口见 [VERIFICATION.md](VERIFICATION.md)。

OrgLoop 的目标是帮助组织中的任何成员提出并持续推进事项，按情境调用 Agent、同事、专家及相应授权者的支持，并把经过验证的经历转化为可复用能力。组织能力增长时，成员也应获得更多理解、行动空间和成长机会。

产品围绕“事项、证据、承接、行动和结果”组织。对话是入口之一，事项在对话结束、模型更换、人员交接和服务重启后仍可继续。模型可以根据新信息修改假设、方案和下一步；系统不试图用穷尽的条件分支替代现实判断。

## 2. 已确定方向、推荐设计与未知

| 类型 | 内容 |
|---|---|
| 已确定方向 | 全公司协作与经验复用目标；人与 Agent 协同；事项推进；前后端分离；可解释的证据和授权；独立验证学习效果 |
| 推荐设计 | 共享的持久事项空间、带来源的知识与资源记录、统一执行通道、候选经验及有版本的 Skill；见 [ARCHITECTURE.md](ARCHITECTURE.md) |
| 组织待确认 | 资源受理责任、优先取舍、授权范围、经验用途与收益、保留期限、风险接受及发布责任；见 [GOVERNANCE.md](GOVERNANCE.md) |
| 尚未知 | 实际组织规模、系统及接口条件、数据质量、内部决策权、投入与效果基线。公开信息和合成案例不能替代内部调查 |

第一版设计与后续验证环境默认禁止真实生产写操作，可使用合成数据、模拟连接器和明确授权的只读资料。接入、业务发送、生产修改、购买和部署需要各自授权，创建公共仓库不提供这些授权。

## 3. 角色与术语

- **成员**：发起问题、贡献证据、申请支持、参与执行和纠错的人。职级不构成提案价值的证明。
- **事项负责人**：保持目标、状态和下一步清楚，协调承接与结果确认；不自动拥有所有资源决策权。
- **资源维护人／专家**：能核实能力或关系线索、表达投入条件、接受或拒绝具体支持请求的人。
- **授权者／业务决策人**：在被组织明确赋予的范围内作取舍、委托动作及接受相应剩余风险的人。
- **知识维护人与评测发布人**：维护证据及经验、组织独立验证、发布和撤回能力。权限需分配，不能因称为专家就自动获得。
- **平台管理员**：维护平台及接入；平台管理权限不自动意味着能读取全部业务内容或裁决业务事项。
- **事项**：一个待理解、探索或实现的目标，可包含未知、调查、协作和多项行动。发起事项不等于组织已经批准投入资源。
- **知识陈述**：某一来源在某一时间提出的内容，可以是观察、陈述、假设或推断；保留核实、争议和修订情况。
- **经验**：有情境、判断、行动及结果依据的经历；未知结果和失败也可保留。
- **Skill**：在明确适用条件、授权和验证范围内可复用的方法或执行能力。发布 Skill 不代表复制了完整的人。
- **Loop**：根据真实反馈修正认识与行动的循环；反复生成、自我评价或新增记忆本身不证明能力改善。

“Builder”与“Seller”可作为创造可用成果、建立沟通与共同承诺的贡献方式，不作为永久员工分类；维护、辅导、预防事故等贡献也纳入经验与反馈。

## 4. 范围与完整性

下表是通用组织的**初始盘点目录**，不是任何公司的完整现状。实施前须核对实际业务、区域、例外和依赖，补齐目录；每项记录负责人、当前系统、接入方式、状态、验收和后续安排。

| 候选业务链 | 贯通结果 | 典型连接对象 |
|---|---|---|
| 商机、方案、报价、合同 | 形成与履约能力相符的承诺 | CRM、合同、知识库 |
| 合同、实施、现场验收 | 范围与变更清楚、交付可检查 | 项目、现场、工单 |
| 业务需求、研发、上线、使用 | 软件可用并验证业务结果 | 需求、代码、测试、发布 |
| 物料需求、采购、仓储、物流 | 正确物料在需要时可用 | ERP、WMS、供应商 |
| 告警、诊断、恢复、复发预防 | 服务恢复且经验可复用 | 监控、工单、资产 |
| 设备进入、使用、维修、退役 | 账实、位置和配置可核对 | 资产、仓储、维保 |
| 人员需求、匹配、到岗、服务 | 有资格且愿意承接的人完成服务 | 人员、排班、服务平台 |
| 验收、结算、开票、回款 | 可核实的经营结果 | 项目、合同、财务 |
| 招聘、培训、法务、财务、行政支持 | 内部支持有承诺与处理结果 | OA及相应职能系统 |
| 知识、经验、决策与能力复用 | 新事项能可靠借鉴既有经历 | 本平台及知识来源 |

所有链路保留在产品目标内，按依赖分批接入。一个链路或模拟场景通过不能替其他链路背书。PMS 等系统缩写及业务含义由实际接入盘点确认。

当前不承诺：全公司已接入、个人经验可全部编码、历史人脉必然可调用、自动给每个人评定价值、模型可准确读取动机、所有经营结果可归因于 AI、每次对话自动训练模型权重。真实人员监控、自动人事处置及无限授权的自主经营不属于本设计范围。

## 5. 功能与质量需求

每项验收由指定场景、契约和运行证据共同支持。场景入口为 [SCENARIOS.md](SCENARIOS.md)，数据与运行约束见 [DATA_MODEL.md](DATA_MODEL.md) 和 [RUNTIME.md](RUNTIME.md)。

### REQ-001 事项与持久工作空间

**范围：** 保存目标、发起者、负责人、相关对象、约束、证据引用、假设与未知、当前方案、行动、阻塞、承接、结果与变更历史。对话摘要是辅助材料，不是唯一状态来源。

**正常行为：** 成员发起事项后，可持续补充证据、申请资源、切换参与者；刷新、重新登录及服务恢复后可继续。新信息允许修订目标或方案，并留下原因。

**边界：** 发起不等于接受或批准；缺资料可进入等待，未获授权或无承接者可阻塞。记录 `open|active|waiting|blocked|completed|cancelled` 仅表达运行情况，不推断业务真相。事项完成需要相应结果依据，不能由子动作成功自动推出。

**可验收证据：** SCN-001、SCN-008、SCN-013、SCN-026 的持久记录与恢复结果；界面能分辨当前目标、未知、负责人和下一步。

### REQ-002 来源、权限与时效感知检索

**范围：** 在当前身份、事项和访问范围下查找资料，返回来源、版本或时间、适用情境及核实状态；支持关键词、业务对象关联和语义候选检索。

**正常行为：** Agent 能引用可见来源，保留来源间差异；进入重要行动前重新检查必要事实和授权有效性。

**边界：** 相似度不证明真实性；来源文字不提供执行授权，也不能覆盖平台指令。没有找到资料不等于事实不存在。过期、撤回、不同意共享或无权限的记录不能通过摘要、缓存、经验、引用或错误提示泄露；有权保留的历史证据以受限方式保存。

**可验收证据：** SCN-006、SCN-007、SCN-014、SCN-015、SCN-025 的检索结果、引用、权限及更正传播记录。

### REQ-003 能力、关系与资源线索

**范围：** 记录具体任务能力、案例、限制、可提供的支持、资源权利、历史接触、当时身份及最近确认，区分能力、授权、可用时间和承接意愿。

**正常行为：** 根据事项提出有证据的支持候选，说明为何相关、哪些仍需确认，允许本人或维护人纠错。

**边界：** 做过一次不等于永久擅长；认识不等于能推动合作；号码相同不证明岗位未变，换岗也不等于关系整体失效。职级不是能力或提案价值的替代指标。只有被授权发现的线索可以展示，资源记录不成为员工价值总分。

**可验收证据：** SCN-001、SCN-002、SCN-003、SCN-016、SCN-025 的候选依据、未知、纠错及可见范围。

### REQ-004 支持请求与真实承接

**范围：** 请求明确需要什么帮助、目的、事项上下文、时限、投入条件和受理者；记录 `pending|accepted|needs_info|declined|withdrawn|expired|fulfilled`。

**正常行为：** 对方接受后形成具体承诺、后续行动和负责人；可补资料、提出条件、拒绝或推荐替代路径。

本人待处理入口提供支持、交接与相关受理事项的最小上下文和对象引用，使尚未加入原事项的人也能发现并处理请求；收到请求不自动获得整个事项或其来源资料的访问权。

**边界：** 推荐名单、发出通知、对方接受和支持实际履行分别记录。沉默不视为接受；接受不等于成果成立。请求跨层级可达性依 POL-001 授权；不按 P0 标签自动路由到最高职级。

**可验收证据：** SCN-001、SCN-003、SCN-004、SCN-005 的受理、拒绝、补充条件、替代路径和实际履行记录。

### REQ-005 决策、委托与授权

**范围：** 记录决策问题、当时事实、关键未知、可选行动、取舍依据、决定人、委托主体、对象、动作、期限、预算和复查条件。授权内容由后端验证。

**正常行为：** 在有效委托内可自动完成适合的动作；需要新的业务承诺或超出授权时，提出具体授权请求并保留事项上下文。

**边界：** 模型建议不能授予自己权限；平台管理员不能默认替组织作业务决定。未决定政策、明确禁止和暂时不可用分别说明。真实生产写操作默认禁用；合成模拟的回执必须标明模拟。损失记录不自动构成对个人失责的判定。

**可验收证据：** SCN-004、SCN-005、SCN-009、SCN-011、SCN-023 的授权校验、越界阻止、模拟标识和责任记录。

### REQ-006 持久执行、幂等与未知结果

**范围：** 持久保存每次动作的身份、事项、授权、来源系统、操作编号、输入摘要、状态及回执。动作状态为 `proposed|awaiting_authorization|ready|executing|succeeded|failed|outcome_unknown|cancelled`。

**正常行为：** 重试或服务恢复先核对既有动作和外部回执；相同逻辑请求不重复产生业务副作用。取消应区分尚未执行、已执行和结果未知。

**边界：** 超时不证明失败；结果未知时不得盲目重做。源系统不支持幂等或查询回执时，应保留未知并交由授权人员核实。无法撤销的已执行动作不能被界面取消伪装成回滚。

**可验收证据：** SCN-012、SCN-013、SCN-023 的超时、重启、重复提交、并发及实际副作用核对。

### REQ-007 实际结果、反馈与纠错

**范围：** 保存真实结果、证据、时间、质量、成本、未完成部分和参与者反馈；区分观察、满意度、归因假设及存在争议的解释。

**正常行为：** 负责人或指定受益者按情境确认结果；新证据能修订记录，历史判断仍可追溯。

**边界：** 动作成功、材料齐全、任务关闭、领导同意、用户点赞不单独证明目标实现。结果滞后、无法归因、执行未发生或意见不一致要保留；不强制为所有事项生成单一成功分数。

**可验收证据：** SCN-008、SCN-010、SCN-021、SCN-026 的分层结果、延后反馈、争议及更正链。

### REQ-008 候选经验、条件与版本

**范围：** 从授权可用的事项经历提出候选经验，关联情境、证据、当时判断、实际行动、结果、限制、反例、贡献者和维护人。

**正常行为：** Agent 生成草稿供相应贡献者或维护人确认、修订、限定用途；失败与未知结果同样可沉淀，但不能被写成已验证成功方法。

**边界：** 原始私人对话或业务记录进入平台不等于允许全组织共享。经验提炼不改变源资料权限；纠错、撤回或来源变更必须定位受影响的派生知识。当前对话适应、新记忆和权重训练分开记录。

**可验收证据：** SCN-014、SCN-016、SCN-017、SCN-026 的候选版本、来源依赖、适用限制、确认及拒绝共享记录。

### REQ-009 Skill 验证、发布与撤回

**范围：** 经验和 Skill 使用 `candidate|evaluating|released|superseded|withdrawn`。发布范围、使用条件、版本、维护与依赖可追溯，发布须具有相应权限和适用验证证据。

**正常行为：** 新能力在未参与提炼的新任务和相关回归上通过约定检查后发布；遇反例、权限撤销或源事实变化时，可限制、替代或撤回，恢复可用旧版本。

**边界：** 反复自评、多个模型意见一致或已知案例重放，不单独证明迁移收益。新权限、组织制度或人事评价规则不能由 Skill 学习自动改写。进行中的任务发现能力撤回时，停止新的相关调用、记录影响并按授权重新判断；已执行事实保持原记录。

**可验收证据：** SCN-017、SCN-018、SCN-021 的发布依据、拒绝发布、影响识别与撤回后调用检查。

### REQ-010 独立评测、反奉承与退化

**范围：** 固定任务条件、模型与 harness 版本、数据范围、评价方式及成本，使用未参与改进的情境与既有回归检验效果，保存失败和未运行项。

**正常行为：** 判断同时支持证据保持与合理更新。事实、目标、约束及实际授权相同，仅改变用户支持态度或名义职级时，不应无依据改变结论；增加有效证据或真实约束后允许修正。

**边界：** 不将反对用户本身视为独立性。模拟结果、合成案例、静态契约检查不等同真实组织收益；困难、长期和失败任务不可从报告中删除以提高成绩。人工审阅和模型评价的覆盖与限制分别记录。

**可验收证据：** SCN-019、SCN-020、SCN-021 和 [VERIFICATION.md](VERIFICATION.md) 的新旧比较、人工投入及未运行状态。

### REQ-011 贡献权益、共享与申诉

**范围：** 展示经验贡献归属、维护责任和使用范围；提供更正能力描述、反馈误用、申请限制用途及申诉的入口，保留受理与处理记录。

**正常行为：** 从实际工作准备经验草稿，允许确认部分可共享方法、以本人协作提供能力或保留不能共享的部分；组织安排维护时间和相应认可。

**边界：** 不承诺所有岗位永不变化，不把分享经验默认解释为允许训练模型或公开私人资料；不用上传量、调用量或 Agent 数自动判断员工价值。具体权利、工作产出归属及收益制度由组织确认，系统不得虚构。

**可验收证据：** SCN-003、SCN-014、SCN-016 的拒绝、范围变更、更正、申诉与后续引用检查。

### REQ-012 全业务连接器覆盖

**范围：** 维护实际业务与系统接入目录，记录接口、数据责任人、权威对象或字段、身份映射、读写权限、同步方式、能力限制、验收状态和未接入安排。

**正常行为：** 通过统一契约接入模拟、只读和获授权的写能力；每项数据带来源与同步状态。系统不可用时说明受影响范围，保留可继续的独立工作。

**边界：** 一个连接器可读不证明全公司打通。重复对象、语义差异、同步滞后及失败不被模型摘要静默覆盖。写回以原系统确认回执为据；原系统不支持的能力保持明确限制。

**可验收证据：** SCN-006、SCN-007、SCN-012、SCN-022 的目录、契约、失败处理和范围核对。

### REQ-013 前后端分离、契约与桌面可用

**范围：** 前端独立构建部署，通过版本化 API 与后端交互；后端承担授权、持久记录、任务执行和模型／集成调用。默认桌面端，界面提供事项、证据、承接、未知、纠错和当前进展。

**正常行为：** 加载、空结果、缺权限、失效授权、服务不可用、并发冲突和恢复均有清楚表现。第一版使用 REST 与游标事件、有限退避刷新；前端恢复以服务端为准。

**边界：** 前端不能直连数据库、持有集成密钥或替后端授权。静态页面和源码不能证明可用性。文档阶段没有应用渲染与交互证据时应明确未运行；用户未要求的移动端不作为本设计验收承诺。

**可验收证据：** SCN-024、[API.md](API.md) 契约及后续独立构建、授权绕过测试和代表性桌面任务的运行证据。

### REQ-014 身份租户边界、审计、预算与可观测

**范围：** 每次数据访问与执行绑定身份、租户、事项、授权及追踪信息；审计关键读取、分享、委托、写入、发布及撤回。记录模型／工具版本、调用成本和失败，限制预算与打扰频率。

**正常行为：** 服务端隔离租户与权限，内部任务与异步 Worker 同样遵守；预算不足、授权过期或异常时暂停新增动作，并说明可恢复路径。

**边界：** 不通过资料引用、搜索命中数量、候选人存在、事件游标或日志泄露越权内容。审计不收集完整的模型内部推理，也不成为员工动作密度监控。成本缺失和未知结果不可被当成零成本或成功。

**可验收证据：** SCN-014、SCN-015、SCN-019、SCN-023、SCN-024 的租户隔离、访问拒绝、预算暂停、恢复和审计检查。

## 6. 完成与效果的判定

文档设计完成，要求需求、治理、场景、API、数据、运行、开发、成本和验证计划相互对应，审查发现有处理记录，静态检查可重现。它不证明应用已实现。

后续功能完成，要求在明确版本和环境中执行相应正常、拒绝、未知、冲突与恢复场景，并核对真实状态和副作用。它不自动证明全公司覆盖或经营收益。

产品效果需在保留失败和困难任务的条件下观察：端到端质量、等待与返工、总人工投入与成本、支持实际兑现、经验迁移，以及成员的理解、选择和行动空间。具体阈值应结合真实基线由组织与产品负责人确定，尚未测量的收益标为假设。相关取舍与验收边界同步到 [DECISIONS.md](DECISIONS.md)、[ROADMAP.md](ROADMAP.md) 和 [REVIEW.md](REVIEW.md)。
