# 开发与交付指南

状态：设计基线 0.1，2026-11-14。当前仓库提供设计、合成场景、接口契约与文档验证工具，尚未实现 Web 应用、API、worker 或生产连接器。下文明确区分现在可执行的文档检查与未来开发任务。

入口：[需求](REQUIREMENTS.md)、[架构](ARCHITECTURE.md)、[数据模型](DATA_MODEL.md)、[API](API.md)、[运行机制](RUNTIME.md)、[场景](SCENARIOS.md)、[治理](GOVERNANCE.md)、[威胁模型](THREAT_MODEL.md)。阶段与执行状态见 [路线](ROADMAP.md)、[验证](VERIFICATION.md)、[审阅](REVIEW.md)。

## 1. 当前可执行环境与命令

本轮实际环境为 Python 3.12.16 和 Node.js 24.22.2。`.venv/` 是本地环境，不进入 Git。当前 Python 依赖仅用于文档、JSON Schema 和 OpenAPI 验证，不是未来应用依赖。

已有环境从仓库根目录执行：

```sh
source .venv/bin/activate
python --version
node --version
python scripts/check_docs.py
python scripts/check_costs.py
python -m openapi_spec_validator contracts/openapi.json
```

新克隆环境需要先准备可用的 Python 3.12；不回退到系统 Python 3.9。解释器已安装时，可建立文档环境：

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-docs.lock
```

`requirements-docs.txt` 表达直接工具依赖，`requirements-docs.lock` 锁定本轮文档工具解析结果。CI 与本地使用同一锁文件；依赖升级需要重新生成锁、运行检查并审查变化。安装命令不代表已在每个操作系统执行，记录以 [验证](VERIFICATION.md) 为准。

上述三项检查只验证各自覆盖的文档、成本计算和接口结构。它们不证明数据库隔离、真实系统集成、桌面交互、Agent 判断或组织效率已经成立。

当前没有 `npm run dev`、应用安装/启动、数据库迁移或 worker 启动命令。不能照抄未来目录为“已经可以运行”。实现相应组件时，维护者必须加入真实脚本、锁文件、配置样例和可重复启动证据，再更新本指南。

## 2. 未来代码目录（尚未实现）

```text
      runtime/            # worker、run、工具调用与恢复
    migrations/           # Alembic 版本化迁移

```

前端独立构建，后端 API 与 worker 分进程发布。它们可以使用同一仓库和同源反向代理，但前端不得直连 DB、保存集成凭据或执行授权决定。桌面是首版交互验收基线。

## 3. 模块依赖与契约维护

- `domain` 不依赖 FastAPI、模型 SDK、网络客户端和前端；不能在实体方法里直接调用模型或外部系统。
- `application` 调用领域规则并管理事务、身份、权限和预算；通过接口使用存储和工具。
- `infrastructure` 实现接口；业务连接器不能直接改动其他领域表或绕过授权执行动作。
- `runtime` 从持久 job/run 恢复并调用正常应用用例，不建立可随意读取全公司的第二条后门。
- API 接受资源标识、目标和动作内容，身份与 `organization_id` 从后端会话推导；禁止客户端自由指定租户或 `acting_as`。

`contracts/openapi.json` 是对外发布的接口契约。实施时从它生成前端请求/响应类型或客户端；不手写另一套相互漂移的 DTO。后端实际导出的 OpenAPI 应在 CI 中进行规范化兼容检查，兼容性规则由实现阶段的工具和用例固定。

契约修改同时审查请求、成功与失败响应、权限、状态、示例、数据模型与场景。修改端点但未同步前端生成物或后端行为不能发布。当前 OpenAPI 结构验证不代表这些端点已经实现。

## 4. 推荐开发顺序与阶段出口

以下次序处理依赖，不缩减全公司目标。所有业务和系统继续保留在接入目录，状态区分计划、模拟、真实只读、受控写入、受阻和不适用。

| 工作包 | 主要产出 | 出口证据 |
| --- | --- | --- |
| E0 确认试运行条件 | 模拟政策、实际数据/身份负责人、接入目录、预算与环境边界 | 所需政策有决定；未确认的能力明确禁用或仅模拟 |
| E1 契约与身份基础 | 独立前端结构、API、会话、租户上下文、错误契约 | 前后端分别构建；直接 API、会话、CSRF、跨租户测试 |
| E2 事务与持续事项 | 迁移、事项版本、事件、job/outbox、run、worker | 幂等、并发、事务原子性、中断恢复和单活动 run 测试 |
| E3 来源与共享检索 | 合成连接器、来源版本、权限依赖、资料与经验检索 | 不同权限的正常检索、更正、撤权、缓存及附件检查 |
| E4 支持与受控执行 | 资源线索、支持请求、授权、模拟工具、回执核实 | 接受不等于履行；越权不执行；超时进入未知并核实 |
| E5 结果与学习 | 结果分层、成员纠错、候选经验、Skill 版本和评测 | 失败/未知保留；未见任务、回归、反奉承和撤回验证 |
| E6 跨场景桌面验证 | 研发、现场服务、资源申请等代表性任务 | 真实渲染/交互、刷新、错误出口、完整推进链证据 |
| E7 授权试运行 | 已批准系统的真实只读，之后单独决定写能力 | 真实身份、来源质量、总人工负担和业务回访；不宣称全业务已接入 |

E0 不要求企业先穷举全部情况。只需明确当前试运行允许什么、谁能决定、何时停止，并让新的未知能被正确呈现和处理。真实企业政策可继续迭代，不能用工程默认替公司签署制度。

## 5. 数据库与迁移实现

1. 先实现组织、成员、事项、版本、事件与 job/outbox，再加入来源、承接、授权、行动和经验。索引依据实际查询与测试补充，不一开始铺设所有专用数据库。
2. 组织相关外键包含 `organization_id`，并通过两个合成组织证明不能串联。来源陈述、模型推断、授权决定、实际回执分表或明确隔离，不能让后写覆盖先前依据。
3. 使用迁移专用账号；运行账号非 owner、非超级用户、无 `BYPASSRLS`。事务设置组织上下文，检查连接池复用和 worker 路径。RLS 是第二道隔离，不能替代应用授权。
4. 业务写入、事件和 job/outbox 同一事务提交。网络调用在事务外执行；条件更新的版本陈旧时不得记录成功事件。
5. 迁移先在可重建的独立 PostgreSQL 环境执行。验证新建、已有数据升级、约束、旧版本兼容和恢复路径；说明性 SQL 不能替代真实迁移测试。
6. 对生产数据采用受控的增量变更、备份和回填策略；破坏性变更先评估读取和 worker 兼容。不能假定所有迁移都能直接执行反向 downgrade。

示意字段、状态和约束见 [数据模型](DATA_MODEL.md)。当前没有应用迁移可运行。

## 6. 工具、模型与连接器开发

### 6.1 工具注册

每个工具版本声明：输入/输出 schema、目标资源、所需授权、读写与外部副作用、预算/超时、幂等能力、回执查询、取消/补偿能力、日志脱敏及网络目的范围。

执行器在模型调用之外验证身份、工具版本、参数、授权、预算和当前 action 状态。模型只产生建议调用；文字中的“董事长已经同意”或来源中的指令都不能提供授权。初版不提供任意 SQL、无限网络或任意生成代码执行工具。

先使用合成工具验证成功、确认失败、执行未知、取消、重复调用和租约失效。工具没有幂等或查询能力时明确保留限制，不用通用重试掩盖。

### 6.2 模型适配

模型接口在后端统一表达上下文、可用工具、预算、结构化输出、用量与失败，不把某个供应商的响应格式散布到前端或领域层。记录模型、提示/harness、工具与价格版本，用于比较质量和成本。

模型输出先做 schema 和资源引用校验；只能引用当前可解析且可访问的来源、人员和授权。用量缺失、限流、超时和无效结构分别处理。重试模型调用仍可能产生费用，必须纳入预算；不能把未知用量当作零。

替换模型需要在同一未见任务和相关回归上比较，包含人工修正和协调成本。价格较低、上下文更长或自评分更高不能直接证明更适合。估算入口见 [成本](COSTS.md)。

### 6.3 连接器

每个连接器先明确：权威对象/字段、读写范围、身份映射、来源版本、权限继承、同步方式、删除/撤权事件、可用性和副作用语义。

先实现合成适配器与真实只读候选，再按具体授权考虑写入。无接口系统可使用经批准的导入与核实，不通过未授权抓取补齐。同步使用可恢复 checkpoint 和去重标识；部分失败必须显示同步延迟与缺失范围。

来源更正和权限撤回要影响检索片段、摘要、附件、缓存、经验和待执行方案。先阻止当前无权访问，再异步重建派生数据；不能等索引更新完成才阻断泄露。

## 7. 测试矩阵

| 层次 | 必测行为 | 证据与限制 |
| --- | --- | --- |
| 文档/契约 | 链接、编号、结构、示例、成本公式 | 当前工具覆盖的静态结果；不代表功能运行 |
| 领域单元 | 版本、状态语义、预算、授权条件、发布撤回 | 验证业务不变量及合理例外，避免只镜像实现 |
| PostgreSQL 集成 | 复合键、事务、RLS、连接池、租约、outbox | 真实受支持数据库；包含非owner运行账号 |
| API 契约 | 正常请求、错误、CSRF、租户、并发和幂等 | 与发布契约一致；直接请求不能绕过 UI |
| 工具/连接器故障注入 | 已成功但超时、回执不可查、中断、重复与撤权 | 外部模拟实际副作用与内部记录核对 |
| Agent 行为 | 依据、未知、来源诱导、职级/态度交换、合理更新 | 固定版本和输入，保留失败；不能只由原作者评分 |
| 学习与复用 | 未见任务、回归、反例、来源失效和 Skill 撤回 | 报告总质量/负担/成本，未知与退化不删除 |
| 桌面端到端 | 发起、读证据、请求支持、核实、纠错、刷新恢复 | 实际渲染和交互；截图不独立证明可用性 |
| 运维与试运行 | 备份恢复、迁移、权限传播、模型故障和积压 | 候选 RPO/RTO 实测；真实业务效果需另外回访 |

具体场景见 [SCENARIOS.md](SCENARIOS.md)，状态与证据见 [VERIFICATION.md](VERIFICATION.md)。测试数据均可重建，真实记录不进入公共 fixture。正式未见评测集必须与优化输入隔离；公开合成场景只能证明其相应覆盖，不能作为隐藏测试泛化证据。

## 8. 真实身份与生产写入门禁

启用真实资料、收费调用或外部动作之前，实施负责人核对相关 POL-001～POL-010 的决定与适用范围。最低需要：实际身份和撤销路径、来源用途与模型出口、凭据保管、显式预算、工具能力、授权者和未知结果承接人。

第一版真实生产写操作默认禁用。开发模拟与生产配置分离，生产启动检查拒绝演示身份、示例凭据和未配置授权的写工具；此项须由测试证明，不能只依赖说明文字。

按连接器、组织与工具粒度启用能力；新 Skill、模型更新或连接器注册不自动获得既有生产权限。平台管理员也不自动拥有经营裁决、所有资料读取或员工评价权。

## 9. 发布、运维、迁移与恢复

每次发布记录应用、契约、迁移、模型/harness、工具、Skill 和政策版本及兼容范围。先确认旧 API/worker 对新增数据能否安全工作，再执行迁移；由单一入口串行执行迁移，避免多副本竞争。

上线先检查日志脱敏、预算、连接器健康、撤权传播、任务积压、未知结果和功能开关。观测以运行健康与问题定位为目的，不采集按键、截图、在线时长等作为员工价值指标。

备份与候选恢复目标见 [架构](ARCHITECTURE.md)。恢复演练必须还原数据库与附件关联、来源权限、任务和回执；恢复后先隔离外部写入，核对恢复点之后可能已经发生的操作，再允许推进。不能用本地回退宣称远端副作用已撤销。

对故障、泄露或错误能力，先限制受影响能力、停止新增副作用、保存必要证据和真实未知，再按相应权限更正、撤回和通知。修复后运行受影响回归，形成简短、可验证的结论，避免把每次偶然成功扩成新规则。

## 10. 贡献与审阅约定

提交只包含本轮负责的项目产出，说明使用中文，解释变化、原因和验证。公开仓库只放通用设计、公开引用、明确的合成资料及脱敏正式结论；不提交真实客户、报销、联系方式、住宿、密钥或原始私人对话。

多人并行明确文件归属，Git 暂存和提交由协调者统一处理。实现者自检不能代替独立审阅；审阅应核对需求、最终变更及实际验证范围。发现变更影响需求或组织政策时，更新 [决策](DECISIONS.md) 和相关契约，不为获得通过静默修改期望。
