# 决策与未决事项

版本：设计基线 0.1；日期：2026-11-14。此页区分用户明确要求、工程推荐与组织待确认政策，避免把设计建议当成企业现行制度。

## 已确定的交付约束

| 编号 | 决定 | 依据与范围 |
|---|---|---|
| D-001 | 前后端分离 | 用户明确要求；独立构建的 Web 前端和独立 API 后端。允许通过同源反向代理交付，不要求增加跨域风险。 |
| D-002 | 全公司协作与能力复用目标 | 任何成员可提出事项，按需要找到人、Agent 与资源；分阶段覆盖，不把整体目标改成单业务问答工具。 |
| D-003 | 本轮交付文档与可检查契约 | 公开仓库、本地克隆、需求/架构/开发等设计、多轮审查。应用实现、生产授权、购买与部署不在当前交付内。 |
| D-004 | 人与智能协同 | 保留成员的判断、选择、纠错与成长；拒绝以在线时长、动作密度或笼统员工价值分代替贡献。 |
| D-005 | 可证伪的学习 | 候选知识和模型自评不能单独证明成效；实际结果、未见事项和退化检查分别保留。 |

## 推荐工程默认（ADR）

| 编号 | 选择 | 理由 | 替代方案与重审触发 |
|---|---|---|---|
| ADR-001 | React + TypeScript + Vite 独立 SPA | 任务协作主要依赖交互，首版无搜索引擎收录或服务端渲染需求；前后端契约清楚。 | 团队已有成熟 Vue 技术能力时可替换前端；需要 SSR 时另评估，不改变 API 边界。 |
| ADR-002 | Python 3.12 + FastAPI，API/worker 分进程的模块化单体 | 模型、检索、连接器与数据处理生态适配；避免早期分布式事务负担。 | 团队的生产运维能力显著偏向其他后端栈时重审；不为概念先进而拆微服务。 |
| ADR-003 | PostgreSQL 为主，基线版本 18 | 对象、关系、授权和事务集中；全文检索及可选 pgvector 优先共用数据库。 | 已有受支持数据库版本需通过兼容验证；只有实测关系/检索负载形成瓶颈才增加专用存储。 |
| ADR-004 | 对象存储 + 来源引用，原系统保留权威记录 | 协作层负责关联与派生经验，避免重新维护多份 ERP/WMS 事实。 | 无接口系统先使用受控导入与人工核实；不能通过无授权抓取补足。 |
| ADR-005 | 版本化 REST 与游标事件 | 易生成前端类型、模拟、测试和恢复；首版按需刷新，活跃任务可有限退避轮询。 | 确有并发与实时性需求后评估 SSE；不预设 WebSocket 基础设施。 |
| ADR-006 | OIDC + 后端会话 + 同源反向代理 | 凭据与授权留在后端；前端与后端部署职责独立。 | 身份提供方尚待企业确认；开发模拟身份只能使用合成数据，禁止在生产启用。 |
| ADR-007 | PG 持久任务/租约/outbox + 独立 worker | 先把承接、暂停、核实与恢复做到可验证。 | 长工作流版本迁移、调度规模或补偿复杂性超过维护能力时评估 Temporal；不承诺外部 exactly-once。 |
| ADR-008 | 模型适配器与后端工具网关 | 经验可跨模型复用；凭据、预算和授权不依赖模型遵守提示词。 | 候选模型须通过同一验证，不以价格或参数名直接认定胜任。 |
| ADR-009 | 候选经验 → 验证 → 版本发布/撤回 | 避免偶然成功、偏好或错误关系被自动升级为组织知识。 | 基线阶段不对公司全部资料微调；有足够可信训练反馈和迁移证据后单独决策。 |
| ADR-010 | 应用权限 + RLS + 派生资料依赖治理 | 覆盖检索、缓存、摘要、附件、历史重分享和工具执行。 | RLS 不能替代应用权限；服务账号不能使用 owner/超级用户/BYPASSRLS；撤权时先阻断读取，再重建索引。 |
| ADR-011 | 桌面为首版验收目标 | 当前没有移动端产品要求；先验证代表性任务。 | 后续提出手机/平板需求时增加对应交互与实机证据；不删除已有移动兼容行为。 |

## 需要组织确认的政策

详细候选规则、责任与反例见[治理](GOVERNANCE.md)。未确认不等于用户已接受；系统可以先用合成政策模拟，不得静默套用到真实组织。

| 编号 | 待确认问题 | 未配置时的边界 |
|---|---|---|
| POL-001 | 发起、受理、拒绝与复核权利 | 可建立模拟事项与支持请求；不声称任何高管已有响应义务。 |
| POL-002 | 资源竞争、时效和风险取舍 | 展示证据、替代路径与未知；不靠 P0 标签自动征用董事长或专家。 |
| POL-003 | 委托、授权和生产写操作 | 所有生产写入、外部通信、资金与设备操作禁用；模拟与建议不等于授权。 |
| POL-004 | 事实、来源和联系人身份确认 | 保留不同说法、来源与时间；未经确认的关系只按授权呈现为线索。 |
| POL-005 | 经验共享、贡献收益和用途 | 仅采用已授权共享的内容；个人经验可以保持由本人参与的支持方式。 |
| POL-006 | 成果判断、试错预算与责任 | 不因任务关闭或主观满意自动认定成功；经营风险与失责的处理规则待确认。 |
| POL-007 | Skill 发布、撤回和维护责任 | 新内容保持候选；未配置发布权限时不启用自动执行。 |
| POL-008 | 访问、撤销、保留与审计 | 默认最小可见；保留期、删除义务、历史审计和既有输出处理需明确。 |
| POL-009 | 成本预算、打扰限制和升级 | 配置明确预算/时限后才能运行相应能力；无预算的收费调用与资源征用不执行。 |
| POL-010 | 全业务接入顺序与回写权威 | 全部业务留在目录，真实系统标为未接入；各阶段事实由相应权威系统确认。 |

## 当前信息缺口与验证方式

- 接口、身份体系、数据处理地域、历史记录质量、真实人员规模和并发均未获内部验证：实施前盘点，不编造现有集成能力。
- 企业是否愿意实际授予跨层级申请、承接和纠错权：用跨部门冲突情境演练，形成正式授权。
- 模型能否在真实任务中可靠判断并减少总负担：使用保留的未见事项和真实回访，不能拿公开合成用例的匹配率代替。
- 建设投入、企业内部资源价、收益分配和开源许可尚待所有者确认：不阻塞设计审阅，不作采购或制度承诺。

## 修改规则

需求调整同步更新需求编号、场景、API/数据模型、验证与成本影响。保留改变的理由和适用范围；过时默认可以撤销。每次修改不自动启动新审批，但不得由 Agent 擅自扩大生产权限或重写组织政策。
