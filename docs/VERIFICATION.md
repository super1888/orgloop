## 2. 可执行设计检查

按[DEVELOPMENT.md](DEVELOPMENT.md)创建Python3.12环境并安装锁定的文档依赖后：

```sh
python scripts/check_docs.py
python scripts/check_costs.py
python -m openapi_spec_validator contracts/openapi.json
```

`contracts/examples.json`包含明确应通过和应拒绝的结构样例；通过格式检查不意味着例中操作者具有实际权限。`evals/scenarios.json`与[SCENARIOS.md](SCENARIOS.md)记录26个公开合成场景，当前全部为not_run，原始私人资料和真实结果不在仓库。

公开用例可以用于开发和回归，不能再称为未见测试。效果评估必须另建未参与提示/Skill改进的新任务集，记录其取得方式、访问范围和是否已被开发者看到；禁止把答案交给被评估流程后声称迁移通过。

## 4. 工程验证设计

### 数据和访问

使用两个以上合成组织、同名对象与不同访问范围。真实运行账号不能是owner/超级用户/BYPASSRLS；直接API、worker、数据库连接池、搜索、附件、事件、缓存、历史重分享和错误路径都要测试。

撤权测试必须在索引尚未重建、已有摘要、旧浏览器会话、已签发下载与在途模型请求等条件下执行。已经送达的内容不能声称可自动收回；测试应确认后续使用/分享/动作被阻断，外部已收到数据依所选服务机制处理。

### 执行和恢复

故障注入点包括：事务提交前后、领取job后、远端操作已成功但本地无回执、租约过期、重复命令、旧worker回写、取消与撤权并发、目标更新及备份恢复。

对每个连接器分别证明幂等、查询回执、撤销/补偿能力。没有能力时验证系统明确停在unknown并交接核实，不能用数据库唯一键冒充外部exactly-once。

### 桌面体验

默认覆盖常见桌面宽度与键盘操作。用代表性成员任务检查：发起事项、读依据、接受/拒绝支持、查看未知、审阅具体授权、纠错、交接、复用经验及恢复。保存实际渲染与交互证据；静态源码、图和建议不能证明可用性。手机/平板非当前验收范围，后续单独确定。

## 5. 模型、harness与学习的验证

1. 先固定待保护行为、任务条件、预算、评价方法与基线；保存模型/工具/harness/资料/政策版本。
2. 分离开发案例、回归案例与未参与改进的新任务。需要人判断时使用可核查证据与多方反馈，保留分歧；不能仅由生成方法的同一个模型给自己评分。
3. 相同事实、目标、约束和实际授权下改变支持态度或名义职级，检查判断是否无依据漂移；增加有效证据或改变目标时，应允许有理由更新。
4. 新旧版本比较质量、总人工时、审核、返工、维护、打扰和工具/模型费用。缺失数据保持未知；不删除困难或长期任务，不把不同任务混成一个总通过率。
5. 发布范围不得超过已验证范围；无优势、退化或证据不足时保留结论并停止扩大采用。撤回后检查新调用、缓存和等待任务。

一次成功或多Agent意见一致都不足以证明普遍改进。动态组织事实继续通过有权限的检索层更新，不默认写入模型权重。

## 6. 产品效果与成员体验

真实试运行前，由业务与成员代表确认要改善的成果、现有方式、结果周期、可接受的质量/风险边界、总投入以及继续投入门槛。当前没有这些实测值，不编造“提升百分比”。

效果观察至少包含：

- 事项是否得到实际承接和解决，等待和返工是否减少；
- 总人工负担与成本是否降低，专家是否被更频繁打扰；
- 成员能否理解更完整的问题、自主行动、取得支持与纠正系统；
- 维护、辅导、预防事故和探索失败是否得到适当解释；
- 是否出现未经授权的行为、误承诺、隐私损害或把分享当作人员价值排名。

任何未授权执行、跨组织泄露、伪造证据或不可核实重复外部动作都应阻止相应能力继续扩大。具体业务收益和容忍阈值由相应责任方在试运行前确定，不由开发者事后为获得通过而调整。

## 7. 报告格式

每次运行记录：范围、不可变版本标识、环境/数据形态、操作步骤或命令、实际结果、失败/未运行/未知、成本、证据位置与责任人。公开仓库只保存去敏的正式结论；受保护的原始记录留在有授权的私有环境。文档审查发现及处理见[REVIEW.md](REVIEW.md)。
