# OrgLoop 组织治理与协作约定设计

## 1. 文档地位

本文件提出可供组织选择和确认的治理设计，**不声称任何公司已接受这些政策**。POL-001 至 POL-010 均为待确认的组织政策；其中明确标注的“推荐默认”用于设计推演、合成数据和模拟验证。真实组织授权、劳动或合同责任、数据权属及保留义务，不能由模型输出或本文件代为确定。

开发可以按照这些边界建设可配置能力。启用真实能力前，需确认与该能力相关的政策、责任人及授权记录；未确认的部分清楚表现为待决策，不擅自解释为已经允许或永远禁止。真实生产写操作在第一版默认禁用。

需求入口见 [REQUIREMENTS.md](REQUIREMENTS.md)，行为例子见 [SCENARIOS.md](SCENARIOS.md)，待决事项索引见 [DECISIONS.md](DECISIONS.md)。

## 2. 基本约定

1. **发起、判断、授权、承接、执行和结果确认分别记录。** 一个人可以承担多个角色，但系统不因此省略实际责任与范围。
2. **人的能力、意愿、可用时间、关系和决策权分别理解。** 具体任务与证据支持匹配，不产生笼统的员工价值分。
3. **事实与取舍分别处理。** 有权者可以决定在不完整信息下如何行动，不能通过拍板把未知变成事实。
4. **自主行动与可纠正性并存。** 有效授权内的适合动作可以自动执行；新情况允许停止、求证、改变方案和申请新的支持。
5. **组织能力与成员能力共同增长。** 知识维护、辅导、协商、预防事故和长期探索都可以贡献价值，不以可见忙碌替代成果。
6. **验证保留失败与未知。** 用户满意、领导同意、任务关闭、资料齐全、动作成功，各自不能证明完整业务结果成立。

## 3. 角色与责任建议

| 角色 | 建议责任 | 不能由称谓自动获得的权利 |
|---|---|---|
| 发起者 | 陈述目标、已知依据与顾虑；参与澄清 | 不因提出想法自动获得他人时间、预算或外部承诺权 |
| 事项负责人 | 保持目标、未知、进度、下一步和结果清楚 | 不自动拥有跨部门资源裁决权 |
| 资源维护人／承接人 | 核实能提供的支持，明确条件，履行或及时修订承诺 | 有历史接触不自动取得代表对方组织承诺的权利 |
| 授权者／业务决策人 | 在授权范围内选择行动、接受剩余风险、说明与复查取舍 | 不将个人偏好变为事实，也不自动取得所有资料访问权 |
| 知识贡献者／维护人 | 核实经验、说明边界、处理更正和失效 | 不单凭一次成功宣布普遍方法 |
| 评测发布人 | 核对独立验证与回归，按权限发布、限制及撤回 | 不以模型互评替代实际效果，也不自动修改组织制度 |
| 平台管理员 | 维护身份接入、基础服务、受限审计及配置 | 不因管理平台就能浏览所有业务、评价员工或分配经营资源 |

董事长、业务负责人和实习生都可以作为实际参与者出现。职级可能关联正式决策权，但不能替代对事项价值、专业能力、关系有效性和可投入资源的核实。

## 4. 组织政策

### POL-001 发起、受理与复核

**目的：** 任何成员的具体问题或想法，都有合理的表达与获得处理的路径。

**推荐默认：**

- 成员可以发起事项并请求组织支持；发起本身不占用尚未获准的外部资源。
- 请求说明具体帮助、依据、未知、期望时限和已有替代路径；Agent 可辅助准备，不能因材料不完美直接否定想法。
- 请求有指定受理范围与反馈路径；受理人可以接受、补条件、拒绝或改派。沉默不视为接受。
- 对拒绝、长期无回应或不同负责人意见冲突，提供有权者复核渠道；直属关系不自动构成拦截所有跨层级申请的权力。
- 跨层级可达性与资源实际投入分别判断，不能把“请求已发送”当作获得支持。

**组织待确认：** 哪些人或委托人受理哪些事项；合理时限及委托覆盖；复核人；探究性想法可申请的最小资源；哪些资料可展示给谁。

**责任与验证：** 公司级授权方明确受理范围，受理角色确认承诺。SCN-001、SCN-003、SCN-004 检查请求不凭职级获得或失去价值，也不绕过实际资源权利。

### POL-002 资源优先与取舍

**目的：** 在目标冲突与信息不完整时，让取舍有依据、授权和可复查记录。

**推荐默认：**

- 分别表达事项价值、时间条件、影响、可恢复性、替代办法和关键未知；不设万能“潜力分”或将它们压成固定个人排名。
- 最高紧急标签不自动意味着董事长处理。路由依据需要什么能力、资源和决定，而非职位高低。
- 发生争用时，Agent 展示双方条件、可能损失及替代方案；有权调配相关资源的人作取舍，并记录复查条件。
- 不确定的新想法可申请有限探索资源，验证后决定下一笔投入；既有竞争者或过去失败仅提供调查线索。
- 维护和事故预防等不显眼工作允许使用合适的证据与反馈周期，不因难以即时计量而被排除。

**组织待确认：** 决策权限、已有合同/SLA 与公司目标、探索预算、跨区域争议归属、紧急时的事先委托及风险接受范围。

**责任与验证：** 资源授权者决定取舍，事项负责人保持执行与反馈。SCN-005、SCN-009、SCN-020、SCN-021 检查系统不虚构唯一正确优先级，也不把持续反对当作独立判断。

### POL-003 委托、授权与生产写操作

**目的：** 明确 Agent 代表谁、针对什么对象、在什么范围内行动。

**推荐默认：**

- 第一版真实生产写操作禁用；合成模拟允许按测试授权执行，但全程标明模拟。
- 真实只读接入也需要相应数据授权。工具是否暴露不构成业务授权，源文中的指令不能授予权限。
- 有效委托至少明确主体、受委托者、对象、动作、目的或事项、有效期及资源边界。必要时规定重新确认条件。
- 授权内、可逆且可核验的动作可以按预先委托自动执行，无需每一步重复请求同样许可。
- 新对外承诺、资金使用、生产系统变更和现场高风险操作按相应政策处理。未配置的写能力保持不可执行，并说明缺什么授权。
- 后端和 Worker 执行授权校验。前端、模型、Skill 和平台管理员均不能自行扩展权限。
- 已发送的外部动作若结果未知，先核实回执；授权过期不得盲目重试，取消也不得抹去已发生的动作。

**组织待确认：** 允许自动执行的动作与金额/资源范围；授权与双人检查要求；现场资格、窗口和恢复办法；代表发送的消息类型；应急委托及撤销生效方式。

**责任与验证：** 授权者接受委托范围，执行系统校验，承接人提供实际回执。SCN-011、SCN-012、SCN-013、SCN-023 检查越界阻止和未知结果恢复。

### POL-004 事实、来源与身份确认

**目的：** 让组织共用认识，同时保留事实差异、历史和当前未知。

**推荐默认：**

- 按对象、字段或业务阶段确定权威来源；现场完工、客户验收、财务结算分别记录，不能合成模糊的“完成”。
- 合并跨系统对象时保留映射依据；同名不自动视为同一人或同一项目，号码未变不证明身份与岗位未变。
- 历史接触关联发生时间、当时身份、证据与核实情况。能否引荐、愿意提供何种帮助和当前资源由相应维护人确认。
- 信息冲突保留原始差异，交给相关事实责任人核实。业务负责人可以决定如何在未知下推进，不能静默改写不方便的事实。
- 来源更正、失效和权限撤回，应定位依赖的摘要、索引、经验和待执行方案，并记录处理情况。

**组织待确认：** 对象与字段的事实责任人、身份合并及拆分责任、哪些来源可保存副本、哪些只保留授权引用、各类事实的复核时机。

**责任与验证：** 数据责任人负责来源确认，知识维护人处理派生内容，事项负责人说明受影响决定。SCN-002、SCN-006、SCN-007、SCN-014、SCN-022 检查事实不会被模型推断覆盖。

### POL-005 经验共享与贡献权益

**目的：** 让经验积累与成员自主、成长及合作意愿相容。

**推荐默认：**

- 从实际交付、评审和复盘生成候选草稿，保留来源与贡献归属，减少重复填表。
- 根据约定区分公司工作记录、可共享经验和个人不愿或不能共享的内容。可发现资源、可读原文、可请求支持和可代表执行分别授权。
- 分享方式可以是公开的限定 Skill、限定群体经验、专家本人参与的支持或 Agent 辅助，不要求把整个人的经验完整提取。
- 提炼、校验、维护和辅导应安排正式时间与相应认可；收益与发展政策由组织确定并能被检查。
- 成员可查看并纠正与自己相关的能力描述，反馈误用、申请变更用途或提出申诉。处理结果与后续影响可追踪。
- 不以文档数、调用次数、Agent 数或显眼项目数量自动评价个人整体价值；不让“分享”默认附带训练模型或公开私人内容的许可。

**组织待确认：** 工作产出和个人经验的使用约定、可确认与可限制范围、贡献认可与收益、维护工时、申请和申诉受理者。

**责任与验证：** 贡献者、维护人与组织授权方分别确认其负责的内容和用途。SCN-016、SCN-017、SCN-018 检查贡献可以纠正、拒绝不自动惩罚、共享能给成员带来实际支持。

### POL-006 结果判断与试错责任

**目的：** 识别有效行动及合理试错，避免用最终得失倒推所有责任。

**推荐默认：**

- 行动回执、支持履行、阶段结果、整体目标及经营影响分别记录；成果由适当角色和证据确认。
- 满意度、参与者反馈和实际观察分别保存；因果无法确定、结果滞后或意见不同，保留未知与争议。
- 在真实授权范围内、如实披露信息并按约定执行的探索，其剩余风险应由组织事先决定是否接受。决策、执行和监督责任分别记录。
- 隐瞒信息、越权和未履行承诺需要另外核查。系统不自动作责任认定或人事处理，发起人也不因提出想法自动承担全部损失。
- 评估包含审核、协调、返工、维护和打扰成本；不要只测模型执行部分的速度。
- 成员能否理解完整问题、自主行动、调用更多支持并纠正系统，是产品效果的一部分。

**组织待确认：** 不同事项的结果确认者、证据与反馈周期、试错投入边界、风险接受人、争议复核及责任处理制度。

**责任与验证：** 决策人在范围内接受风险，负责人回访结果，核查角色独立处理争议。SCN-005、SCN-010、SCN-021、SCN-026 检查未知、失败和长期任务不会被删除或误记成功。

### POL-007 Skill 验证、发布与撤回

**目的：** 让可复用能力在有证据的范围内增长，并允许失效与恢复。

**推荐默认：**

- 候选经验保留原经历、适用条件、反例与维护人；从草稿到发布有明确版本和相应权限。
- 验证使用未参与提炼的任务及相关回归，同时记录成本与人工负担。模型评价可帮助发现问题，不能单独证明真实效果。
- 原专家和方法作者的参与不替代独立验证。真实反馈不足时，只发布相应范围的试用能力或保留候选，不夸大成效。
- 撤回和替代要影响检索及新的执行；识别进行中的依赖任务，交由相应责任人重新判断，不改写历史动作。
- 学习过程可提出知识、Skill、工具或策略改进；新增业务权限、考核或分配制度由相应授权者另行决定。
- 记录本次改进改变了什么。经验新增、harness 更新和模型权重训练不得混为一谈。

**组织待确认：** 发布与撤回责任、适用评价、试用范围、允许自动发布的条件、回归要求、退化处理及受影响任务的处置人。

**责任与验证：** 维护人提议，评测发布人核对独立证据，事项负责人处理任务影响。SCN-017、SCN-018、SCN-019、SCN-020、SCN-021 检查迁移、合理更新、退化和撤回。

### POL-008 访问、撤销、保留与审计

**目的：** 共享必要认识，同时保护来源权限和可纠正性。

**推荐默认：**

- 服务端依据身份、租户、资源及事项授权作访问决定，异步任务、搜索、引用、事件、缓存和日志同样遵守。
- 仅授权发现的资源线索才能展示。对无权发现的资料，返回相应的缺信息或请求渠道，不能通过“有一条秘密关系”泄露其存在。
- 商旅经验可共享协议资源与服务建议；个人住宿轨迹、私人联系方式和原始报销不因此全员可见。
- 权限撤销停止后续无权访问与使用，更新关联派生内容；历史记录中有必要保留的证据采取受限访问，保留和删除依组织确认的义务处理。
- 审计保存关键访问与动作、授权依据、模型和工具版本及判断依据摘要；不要求保存完整模型内部推理，不以在线时长和动作密度监控成员。
- 生产保留期限、删除期限、审计访问和备份恢复政策尚待组织确认。模拟环境仅用可重建的合成内容。
- 公开仓库只保存通用设计、公开来源和标明合成的案例，不放真实组织、客户、联系人、报销、差旅、密钥或原始私人对话。

**组织待确认：** 身份来源、租户边界、数据分类、发现与读取权限、撤销传播要求、保留/删除及备份期限、审计访问职责、模型供应商的数据处理条件。

**责任与验证：** 数据和身份责任人确认范围，平台落实控制并接受独立核查。SCN-014、SCN-015、SCN-024、SCN-025 验证隔离、最少披露、纠错与撤销传播。

### POL-009 预算、打扰与委托资源控制

**目的：** 避免把自动化执行与请求能力变成无限消耗或持续打扰。

**推荐默认：**

- 按事项、委托及服务记录资源边界与消耗，涵盖模型、工具、人工审核、专家支持和外部服务。缺失成本保持未知。
- 真实购买和新增付费资源需相应授权；文档中的成本估算不构成采购许可。
- 预算或有效授权不足时停止新增动作，说明影响并允许补充授权、缩小行动或取消；不能静默降级任务目标以伪装完成。
- 支持请求、提醒与升级遵守受理范围和打扰政策；重复失败、无人承接或未获允许时，不自动群发或跨渠道轰炸。
- 取消前核对正在执行及结果未知的动作；取消后保留实际成本、已发生效果和剩余责任。

**组织待确认：** 预算单位与上限、提醒频率、允许联系对象与渠道、超支和无人响应的处理人、应急资源委托。

**责任与验证：** 预算和资源授权者确认额度，系统计量与暂停，事项负责人协调恢复。SCN-005、SCN-012、SCN-023 检查预算、打扰、取消和未知动作。

### POL-010 全业务接入与权威回写

**目的：** 保持全公司目标，同时明确每次接入实际覆盖的范围和限制。

**推荐默认：**

- 全业务目录先盘点再补齐，每条链保留系统、接口、数据责任人、状态、建设安排和验收证据。未接入、受阻和不适用均明确记录。
- 不要求一次迁移所有数据库。原系统保留其权威业务记录，本平台关联标识和必要的授权副本、引用及派生知识。
- 连接器分别声明模拟、只读与写能力，支持的身份、对象、动作、回执查询和幂等限制；不可用时说明影响。
- 原系统确认的写入与本平台事项状态关联，不能仅因模型判断或消息发出就认定同步成功。
- 接入一种系统或一个业务场景通过，仅证明其检查范围；不能升级成“所有系统已统一”或“全公司效益已证明”。

**组织待确认：** 真实业务目录及负责人、各接口和权威来源、身份映射、接入授权、同步和撤销要求、阶段顺序与范围验收。

**责任与验证：** 业务和数据责任人共同确认接入契约，平台实现，独立验证覆盖与限制。SCN-006、SCN-007、SCN-012、SCN-022 检查状态语义、失败回写和覆盖完整性。

## 5. 需要保留的分歧与未知

组织目标、客户利益、成员成长、短期资源和长期探索可能冲突。系统应呈现可核实依据与不同解释，提供实际决定和反馈渠道，不承诺消除所有冲突。

当组织尚未决定某条政策时，产品可记录问题、调查和方案，明确哪些行动等待决定。允许有效授权内的独立工作继续；不能以缺一项政策为由禁止所有调查，也不能以“推进”为由替企业作出未授权承诺。

治理政策变更应记录内容、理由、决定者、适用范围、生效时间、受影响授权及事项。新政策不自动改写过去已发生的事实和责任记录。相关技术与运营机制见 [ARCHITECTURE.md](ARCHITECTURE.md)、[RUNTIME.md](RUNTIME.md) 和 [DEVELOPMENT.md](DEVELOPMENT.md)。
