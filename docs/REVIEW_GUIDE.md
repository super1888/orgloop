# 设计审阅指南

这份基线供产品与工程讨论使用，尚未实现应用。建议先读本页与[需求](REQUIREMENTS.md)，再按问题进入专项文档；不需要一次阅读全部接口schema。

## 1. 已保留的目标

- 全公司业务和职能进入同一协作与覆盖体系，分批实现不缩减整体目标。
- 每个人可以发起事项，按实际问题申请必要支持；资源可达性与真正投入分别成立。
- 个人经验通过有来源、有条件、有贡献归属的方式复用，成员也获得支持、成长和纠错能力。
- Agent可以在未知中调查、比较与调整；执行、权限和记录具备可检验约束，不穷举现实全部if/else。
- 真实结果与新事项验证决定经验是否有用；提示词、自评和对话次数不足以证明进化。
- 前后端分离。公共仓库与公司私有数据环境分开，当前没有生产接入、收费采购或部署。

## 2. 本次推荐方案

独立React/TypeScript前端、Python/FastAPI API、独立持久worker、PostgreSQL和对象存储；模型和连接器可替换。先用模块化单体把事项持续推进、来源权限、实际承接和经验验证做清，再根据实测负载扩展。

选择理由及替代触发见[DECISIONS.md](DECISIONS.md)，不是声称该技术组合对所有团队都最优。模型候选通过相同任务评测后确定，价格表不能代替能力证据。

## 3. 优先讨论的六个决定

| 事项 | 当前处理 | 需要所有者/组织明确的部分 |
|---|---|---|
| 跨层级支持 | 接受式请求，有拒绝与复核出口 | 谁受理、时限、委托与资源竞争规则 |
| 经验共享 | 来源/贡献/用途/纠错/版本可追踪 | 共享约定、维护工时、收益与成长支持 |
| Agent行动 | 初期真实写禁用，模拟与建议可推进 | 允许自动执行的对象、动作、预算和风险 |
| 共同事实 | 按来源、阶段和时间保存差异 | 各类权威源、责任人及接口/身份条件 |
| 学习与成效 | 候选经验、新事项验证、退化可撤回 | 真实结果确认、反馈周期、继续投入阈值 |
| 建设投入 | 可复算用量和部署参考 | 实际团队、地域、内部资源价和总预算 |

这些未知不应由Agent替公司作决定。政策候选与边界见[GOVERNANCE.md](GOVERNANCE.md)。

## 4. 审查证据怎么看

[REVIEW.md](REVIEW.md)记录多轮独立审查的具体发现和处理；[VERIFICATION.md](VERIFICATION.md)区分静态检查、未来运行测试和用户验收。当前公共用例全部标为合成、未执行产品验证，不是隐藏的未见任务，更不能据此宣称模型迁移已通过。

提出修改时请指出：哪个目标/场景受影响、具体行为应怎样变化、为什么，以及怎样检查改动有效。审阅者可以推翻推荐默认；需求、架构、API、数据、开发与验证需要同时保持一致。
