# 成本、价格口径与预算方法

状态：设计预算，未采购、未部署、未运行收费模型评测。查价日：2026-11-14，日期按 Asia/Bangkok。公开报价会变化，采购前须重新核对。

## 1. 推荐与使用边界

首版采用可替换的模型适配层，以自管或已有受控环境验证完整协作能力。已有服务器、人员和接口也有成本，不能按“免费”计入收益。托管数据库作为减少部分运维工作的备选。

本文件中的境外公开云和 API 价格是便于复算的外部价格基准，**不等于采购建议，也不代表允许把组织数据发送给相应服务**。真实选择需要同时满足模型效果、服务地区、网络、数据处理约定、恢复目标和组织采购条件。不得通过代理规避服务地区限制。

尚未获得购买资源、创建付费账号、接入生产数据或部署服务的授权。本轮只交付文档和合成算例。未做模型效果、吞吐、容量、恢复与真实人效测试。

## 2. 可复核的模型价格快照

单位：USD／百万计费 tokens。OpenAI 采用 Standard、输入不超过 272K tokens 的短上下文价格；DeepSeek 采用峰时、未缓存输入价格。以下均不扣促销或缓存优惠。

| 价格配置 | 输入 | 输出 | 说明 |
|---|---:|---:|---|
| GPT-6 Luna | 0.10 | 0.50 | OpenAI Standard 短上下文 |
| GPT-6.1 Sol | 2.00 | 10.00 | OpenAI Standard 短上下文 |
| DeepSeek Flash | 0.30 | 1.20 | 峰时、未缓存；查价时模型名为 deepseek-flash |
| DeepSeek V4 Pro | 1.32 | 3.96 | 峰时、未缓存；模型名 deepseek-v4-pro |
| text-embedding-3-small | 0.02 | 不适用 | 文本向量化输入，不含数据库索引与运维 |

来源：[SRC-PRICE-OPENAI](SOURCES.md#src-price-openai)、[SRC-PRICE-LUNA](SOURCES.md#src-price-luna)、[SRC-PRICE-SOL](SOURCES.md#src-price-sol)、[SRC-PRICE-DEEPSEEK](SOURCES.md#src-price-deepseek)、[SRC-PRICE-EMBEDDING](SOURCES.md#src-price-embedding)。结构化快照见 [rates.json](../pricing/rates.json)。

### 2.1 账单口径

- 输出指供应商 usage 中的**总计费输出**，包括适用的推理 tokens，不能只统计用户看见的最终文字。OpenAI 将推理 tokens 按输出计费；DeepSeek Responses usage 将推理计入输出明细。适配器必须保留供应商原始 usage，并映射为归一化账单字段。来源：[SRC-BILLING-REASONING](SOURCES.md#src-billing-reasoning)、[SRC-BILLING-DEEPSEEK](SOURCES.md#src-billing-deepseek)。
- OpenAI 两个配置的缓存命中输入分别为 0.01、0.10 USD／百万 tokens；缓存写入另有费率。Batch／Flex 公开价为 Standard 的 50%，Fast 为适用 Standard 的两倍。本算例不预设任务适合异步批处理，也不预设一定命中缓存。
- 这两个 OpenAI 配置的 API 输入超过 272K 时，整次请求的输入及缓存费率为两倍、输出为 1.5 倍；可用的地区处理另有 10% 附加费。具体端点、资格与版本须重核。本预算的 8K 输入假设不触发长上下文加价。
- DeepSeek 官方谷时费率为峰时一半；峰时为工作日 UTC 01:00—04:00、06:00—10:00，排除中国法定节假日。缓存命中另有费率。预算以峰价避免依赖调度优惠。
- 调用工具可能另收费。例如 OpenAI 普通 Web search 列价为 10 USD／千次，并另计适用搜索内容 tokens；DeepSeek Search 与 Fetch 各为 0.75 USD／千次。内部业务系统调用、第三方许可、OCR、媒体和其他托管工具不包含在基础文本表中。
- 货币转换、税费、支付手续费、合同折扣和供应商区域差价未纳入。模型的实际计费、速率限制与支持地区以账户和合同为准。

### 2.2 可替换不等于等效

价格表不证明这些模型具有相同质量或 token 用量。价格较低的模型是否适合事实提取、事项推进或资源匹配，需要在同一组未见任务、权限反例和真实结果上测试。能力不达标时不能用“便宜”解释接受错误。

建议先比较候选模型，再决定日常与复杂任务的路由比例；不得默认强模型只需处理 20% 任务。模型切换还需复核工具协议、输出 schema、拒绝行为和 usage 口径。动态事实、关系和可撤销资料优先保留在检索层，本预算未包含模型权重训练。

## 3. 合成用量与模型敏感性

以下是规划假设，**不是当前组织的实测业务量**。事项数也不等于活跃用户数或并发量。

| 输入变量 | 假设 | 需要实测的原因 |
|---|---:|---|
| 每事项模型调用 | 6 次 | 调查、工具反馈和协作等待可能改变调用量 |
| 每次平均输入 | 8,000 tokens | 必须包含检索材料、历史和工具返回 |
| 每次平均总计费输出 | 1,000 tokens | 必须包含适用推理 tokens；复杂推理可能远超此值 |
| 额外 token 预算 | 基础量的 30% | 为重试与评测预留，非已测得的固定比例 |
| 人工复核 | 10% 事项，每次 5 分钟 | 仅算复核，其他协作、执行与维护工时另计 |

计算方式：

    月输入 tokens = 事项数 × 调用次数 × 每次输入 × (1 + 额外预算比例)
    月输出 tokens = 事项数 × 调用次数 × 每次总计费输出 × (1 + 额外预算比例)
    模型月费 USD = 月输入 / 1,000,000 × 输入单价 + 月输出 / 1,000,000 × 输出单价
    人工复核小时 = 事项数 × 复核比例 × 每次分钟 / 60

| 月事项数 | 500 | 5,000 | 50,000 |
|---|---:|---:|---:|
| 含预留的输入／输出，百万 tokens | 31.2／3.9 | 312／39 | 3,120／390 |
| 全部使用 Luna，USD | 5.07 | 50.70 | 507.00 |
| 全部使用 Sol，USD | 101.40 | 1,014.00 | 10,140.00 |
| 全部使用 Flash 峰价，USD | 14.04 | 140.40 | 1,404.00 |
| 全部使用 Pro 峰价，USD | 56.63 | 566.28 | 5,662.80 |
| 80% Luna＋20% Sol，USD | 24.34 | 243.36 | 2,433.60 |
| 80% Flash＋20% Pro，USD | 22.56 | 225.58 | 2,255.76 |
| 人工复核小时 | 4.17 | 41.67 | 416.67 |

混合配置的百分比指**输入和输出计费 tokens 各自的份额**，不是调用数或事项数份额。复杂请求通常更长，按调用数混合会低估强模型成本。表中单模型比较只是把同一假设分别代入价格，不能推出模型质量相同。

算例变量及未四舍五入的期望值见 [scenarios.json](../pricing/scenarios.json)。每事项调用数、输入或输出量翻倍时，相应费用线性增加；大量多 agent 互相复制上下文可能进一步放大用量。Embedding 一次处理 1 亿 tokens，在该单价下为 2 USD；重建、查询向量化、OCR 和索引资源另计。

## 4. 两种部署价格基准

以下资源量也是预算假设。前后端在逻辑与构建上分离，并不强制首版购买两台服务器；验证环境可在一台 VM 中部署独立静态前端、API 和 worker。

| 项目 | 自管验证环境 A | 托管数据库环境 B |
|---|---:|---:|
| Lightsail Linux、公开 IPv4、8GB RAM／2vCPU／160GB SSD | 44.00 | 44.00 |
| Supabase Pro 订阅 | — | 25.00 |
| Supabase Large 数据库计算 | — | 110.00 |
| 每月数据库计算额度抵扣 | — | −10.00 |
| 假设平均保留 160GB 的 VM 快照，0.05 USD／GB月 | 8.00 | 8.00 |
| R2 Standard 合计 110GB月，扣一次 10GB 免费量，0.015 USD／GB月 | 1.50 | 1.50 |
| **固定资源小计 USD／月** | **53.50** | **178.50** |

来源：[SRC-PRICE-AWS](SOURCES.md#src-price-aws)、[SRC-PRICE-SUPABASE](SOURCES.md#src-price-supabase)、[SRC-PRICE-R2](SOURCES.md#src-price-r2)。160GB 是平均实际保留的快照计费量假设，不是保留任意天数快照的包价。110GB 对象用量包含一份 50GB 文档、其 50GB 备份和 10GB 数据库导出；免费量在账户层面只扣一次。

R2 算例假设全账户月 Class A 不超过 100 万、Class B 不超过 1,000 万，且使用 Standard 存储，因此操作费在免费量内。超出后分别为 4.50、0.36 USD／百万次。直接 R2 出网无费用，不代表其他连接服务或源站传输免费。

### 4.1 方案选择

- A 的应用和数据库共用故障域，适合受控验证，不能据此承诺公司级高可用。团队自行承担补丁、备份、权限配置、监控和恢复工作。已有内网 VM 也应按资源、运维和备份的内部真实成本替换 44 USD 参考项。
- B 将数据库运维部分托管。这里使用 Large 8GB、专用 2vCPU 的公开档位，不能把仅含 Micro 的 25 USD 基础订阅当成同等资源。托管并不消除应用、授权、备份策略和恢复验证责任。
- Supabase Pro 的每日备份保留 7 天；PITR 另从 100 USD／月／7天保留起。本算例未包含 PITR，不能支持短于日备份间隔的数据丢失承诺。对象备份与 VM 快照也不能自动证明恢复可用。
- 同一供应商内多副本不等于独立灾难恢复。生产环境的跨故障域副本、独立凭据和恢复演练需要另行设计与计价。
- **表中的单机资源不证明能承载 5,000 或 50,000 事项。** 高档模型用量只是敏感性情境；应用、数据库、队列、检索与备份容量须用真实并发和数据量测试后重估。
- 一套资源中混用多个供应商只是价格比较，不能直接作为建议生产拓扑。网络往返、区域、带宽、出域限制和运维复杂性需要一起比较。可在允许的同一区域选择等效服务后重新报价。

## 5. 总成本与人工

模型费之外至少还要记录：

1. 真实业务处理、专家承接和请求协调工时。
2. 连接器开发及维护、系统升级适配、权限核对、经验确认与评测。
3. 运行监控、事故响应、备份和恢复演练。
4. 原系统 API／企业许可、SSO、外部工具、日志、网络与供应商支持。
5. 首次开发、数据清理、培训、组织规则确认和变更沟通。

建议账本分开记录以下公式中的各项，避免把正常业务处理误算为全部新增成本，也避免忽略系统带来的额外协调负担：

    总月成本 CNY =
      FX × (基础设施 USD + 模型/外部工具 USD)
      + 各类实际人工小时 × 各类综合小时成本 CNY
      + 许可/支持/税费及其他实际成本 CNY

FX 与综合小时成本均保留为组织财务确认的输入，本文件没有编造实时汇率或薪资。月 5,000 事项、复核 10% 的例子，单复核即约 41.67 小时；这尚未包含专家实际解决问题的时间。

首次建设应按开发文档中的工作分解估算人员周数和集成缺口，再由实际团队、接口条件和交付标准核价。当前没有足够证据给出固定开发报价。

## 6. 预算控制与效果验证

以下是建议默认，需要组织在接入前确认：

- 记录事项、run、模型配置和工具调用的实际 usage；缓存、推理和工具费分别记账。
- 给每次 run 设置计费 token 与工具调用预算；达到预算后保存状态、说明当前结果并请求新的授权，避免无限自我复盘。
- 整理知识采用可恢复的异步队列和增量更新，源资料未变化时避免重复嵌入；模型升级产生的新维度或语义差异需计划重建。
- 先以合成数据和授权范围内的资料做效果与成本对照；不得为省钱绕过权限、减少必要验证，或把实验数据暴露给未获准供应商。
- 比较相同任务的交付质量、总人工投入、总耗时、返工与实际支出。模型更便宜、任务关闭更多或调用量上升，不单独证明人效提高。

正式选择需同时具备：模型与工具能力证据、数据处理边界、恢复与容量测试、真实 usage 样本及可接受的总成本。价格静态复算只证明算术与假设一致。
