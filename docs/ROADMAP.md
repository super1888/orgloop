# 开发与业务覆盖路线

状态：设计规划，2026-11-14。尚未开发应用或接入生产系统。阶段依据依赖和验收证据推进，不能把时间估计当作效果承诺。具体团队、接口条件、投入与周期需要盘点后校准。

## 1. 全公司目标和逐步实现

任何成员提出事项，系统按上下文找到人、Agent与资源，形成实际承接；结果能回访，经验能带条件复用。全业务进入覆盖目录，某条链尚未实现也要保留状态、负责人和后续安排。

下表为**初始盘点目录**，不是某家企业内部流程已经完整核实的断言。

| 业务链 | 关键共同对象 | 当前接入状态 | 需要取得的验收证据 |
|---|---|---|---|
| 商机到可执行合同 | 客户、方案、范围、报价、承诺 | 未接入，接口与责任人待确认 | 承诺与交付条件一致，缺信息有处理出口 |
| 合同到项目验收 | 项目、现场、资源、变更、证据 | 未接入 | 范围、变更和实际验收可追溯 |
| 业务需求到软件上线及使用 | 需求、版本、测试、部署、反馈 | 未接入；有合成场景 | 业务确认、工程交付和使用结果分别验证 |
| 物料需求到现场可用 | 规格、采购、库存、物流、备件 | 未接入 | 账实、可用与资源预留由权威来源确认 |
| 报障到恢复及复发预防 | 资产、事件、工单、变更、根因 | 未接入；有合成场景 | 恢复与重复故障变化，保留未知归因 |
| 设备进入到维修与退役 | 序列号、位置、配置、所有权 | 未接入 | 生命周期证据和实际位置一致 |
| 人员需求到合格服务完成 | 能力、资格、可用性、承诺 | 未接入 | 匹配后获得承接，支持履行有证据 |
| 验收到结算回款 | 合同、验收、费用、发票、应收 | 未接入 | 完工、验收与财务阶段分别成立 |
| 招聘、培训、法务、财务及行政支持 | 申请、依据、决定、交付 | 未接入，需继续拆分 | 请求、受理、结果和复核路径完整 |
| 经验复用与跨部门资源协调 | 案例、Skill、支持请求、决策 | 未接入；有合成场景 | 未见事项复用、风险取舍、成员成长 |

每条实际业务补充：负责人与权威系统、对象映射、读写能力、接入许可、来源/撤权时效、业务例外、实施安排与验证结果。PMS的具体含义以所接系统为准，不根据缩写猜测业务对象。

## 2. 实现阶段

### 阶段0：设计基线（本轮交付）

交付需求/政策/场景、前后端分离架构、数据与API契约、成本算例、威胁模型与验证计划。完成跨作者审阅、修正和静态检查。退出条件是材料可审阅、契约一致、未知明确；不是产品已经可用。

### 阶段1：本地合成端到端环境

先建立独立前端/API/worker、身份模拟隔离、事项与来源、人员资源请求、工具模拟、结果和候选经验。使用研发、现场服务、跨层级支持等不同情境验证共同机制。补齐API的回读、交接、拒绝、纠错、用途控制和恢复路径，而非只做一次聊天演示。

退出条件：独立构建与启动，正常/拒绝/未知操作可用，重启恢复与权限测试通过；显示全部数据为合成。生产身份绕过和真实写连接器不得启用。

### 阶段2：授权只读与受控试运行

确认身份、资料用途、数据处理地区、来源权限、事实责任人与预算，接入实际允许的数据。保存同步延迟和缺口，验证来源修订/撤权与派生内容治理。把共同基础扩展到覆盖目录的各业务，不把一个案例通过等同完整覆盖。

退出条件：实际数据范围内的身份与隔离、来源时效、纠错、隐藏关系及检索质量有证据；代表性成员任务有实际交互证据。未获确认的政策只允许记录与调查，不扩大执行权限。

### 阶段3：明确委托内的行动与承接

按工具和业务范围逐项开放已获授权的操作。先验证幂等、超时核实、取消、撤权、恢复和真实承接，再承担业务效果。生产写入不得由设计文档、模型建议或模拟测试自动获得许可。

退出条件：授权与回执闭合，故障注入不造成盲重试，真实副作用可核实；有人持续负责，争议和拒绝有出口。涉及资金、设备、客户承诺等由相应政策另行核准。

### 阶段4：经验发布与持续效果验证

候选经验/SKill通过新事项和回归验证后在明确范围发布，观察是否减少总负担并维持质量。新增反例或退化能撤回，保留贡献与维护。模型、工具、harness与知识更新分别比较；是否训练权重另行决策。

退出条件：独立证据支持相应范围的改善，包含失败、成本、审核负担和成员体验；无优势则缩小方法适用范围或停止采用该改进，不改变全公司的建设目标。

## 3. 实施前的必要工作

公司级发起方、业务链负责人、产品、工程、数据/系统责任人及一线成员共同确认范围。首先完成系统与身份盘点、跨部门真实案例、现有人工方式基线及组织授权。核心实施团队配置、连接器数量和预计人月需要这些输入后估算；不使用云主机价格代替项目预算。
